# M04 GRPO 优势与 KL · `GRPO` `RL 后训练` `RLVR`

**入口（照念）**：「这是 GRPO 的 loss，每个 prompt 采 G 条。」　**时长** 8–12 分钟

| 级别 | 问题 | 说明 |
|---|---|---|
| P0 | 优势在**整个 batch** 上归一化，而不是在组内 | 实测：一组 4 条全对，组内优势应全为 0，全局归一化后变成 +0.54 → 模型被奖励去做"本来就会的题"。应 `view(B, G)` 后按组算 |
| P0 | 标准差没有加 eps | 整个 batch 奖励全相同时 0/0 = NaN（实测）。组内版本更常见：一组全对或全错 |
| P1 | KL 的 k3 估计方向反了 | 采样来自 π 时，KL(π‖ref) 的 k3 是 `exp(ref - logp) - (ref - logp) - 1`。实测真值 0.5，正确写法 0.500，题中写法 1.22，而且 π ≫ ref 时指数爆炸 |
| P2 | 每条序列先按长度平均再平均 | GRPO 原版做法，但会让长回答中每个 token 的权重变小（DAPO 等改成全局 token 平均）。能说出差别即可 |

**追问 · 预研**：组内除以标准差会带来什么偏差（难度偏置）？KL 放在 reward 里和放在 loss 里有什么不同？被截断（没生成完）的回答应该怎么给奖励？
**追问 · 落地**：G 取多大？rollout 的成本占比？在智驾里，规则可验证的奖励（RLVR）可以是什么？奖励被"钻空子"（reward hacking）时你会怎么发现？

**锚点**：4 = 找到组内归一化和 eps，并能讨论 KL 方向；3 = 找到组内归一化；2 = 只找到 eps；1 = 不清楚"组"的含义
