# M06 VLM 视觉 token 拼接 · `VLM` `VLA` `多模态`

**入口（照念）**：「这是把图像特征塞进 LLM 输入的代码。」　**时长** 8–10 分钟

| 级别 | 问题 | 说明 |
|---|---|---|
| P0 | 一张图只有 1 个占位符，却有 256 个视觉 token | 实测直接报 shape mismatch。需要先把占位符展开成 256 个（同时扩展 attention mask、labels、位置编码） |
| P0 | 图像位置的 labels 没有设为 -100 | 修好形状后依然会让模型去"预测 IMAGE_ID"，静默地浪费容量、污染 loss |
| P1 | 多图、多样本时 `flatten(0, 1)` 的顺序 | 必须和占位符在 batch 中出现的顺序完全一致，否则图 A 的特征会放到样本 B 里，不报错 |
| P2 | 对 embedding 输出原地赋值 | 一般可以反传；但如果 embedding 被冻结或做了 `no_grad`，视觉部分的梯度路径要确认 |

**追问 · 预研**：视觉 token 数量（256 vs 动态分辨率）对效果和速度的影响？视觉 token 用什么位置编码（1D 连续 vs 2D/M-RoPE）？
**追问 · 落地**：车上 6–11 路相机，每路 256 token，上下文和延迟怎么控制（token 压缩、时序复用、KV cache 复用，关联旧题库 D04）？

**锚点**：4 = 两个 P0 + 顺序问题，能讲清 mask/位置同步扩展；3 = 两个 P0；2 = 只看到形状问题；1 = 不清楚视觉 token 怎么进 LLM
