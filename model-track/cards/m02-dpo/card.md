# M02 DPO 损失 · `DPO` `偏好对齐` `LLM 后训练`

**入口（照念）**：「这是 DPO 的 loss，你看看。」　**时长** 8–12 分钟

| 级别 | 问题 | 说明 |
|---|---|---|
| P0 | `seq_logp` 没有错位 | 同 M01：`logits[:, :-1]` gather `ids[:, 1:]`，mask 也要跟着错位 |
| P1 | 除以 `resp_mask.sum` | 标准 DPO 用**序列 log-prob 之和**。按长度平均是另一个目标（类似 SimPO/长度归一化），会改变对长短回答的偏好。要能说出这不是"等价"改动 |
| P1 | ref 前向没有 `no_grad` | 如果 ref 参数已冻结，结果不变但浪费显存和计算；如果 `ref` 和 `policy` 其实是同一个对象（常见事故），两个比值完全抵消，loss 恒为 log 2 |
| P2 | `log_softmax` 在 bf16 下做 | 词表很大时精度损失，影响 logp 差值；通常先转 float32 |
| 诱饵 | "prompt 部分也该算进来吗？" | 即使算进来，chosen 和 rejected 的 prompt 相同，policy 与 ref 的 prompt 项会**完全抵消**。能推出这一点的候选人加分 |

**追问 · 预研**：从 RLHF 目标推一下 DPO 的隐式奖励是什么？β 变大变小分别意味着什么？为什么 DPO 训练中 chosen 的 log-prob 也常常下降？
**追问 · 落地**：偏好数据从哪里来（人工标注 / 规则 / 模型打分）？离线 DPO 和在线采样再 DPO，各自的数据新鲜度问题？在智驾里，什么样的"偏好对"是可信的？

**锚点**：4 = 找到错位、说清 sum/mean 的目标差异、推出 prompt 抵消；3 = 错位 + 一个 P1；2 = 只能复述公式；1 = 说不清 DPO 的输入是什么
