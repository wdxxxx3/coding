# M10 世界模型评估 · `World model` `视频预测` `仿真`

**入口（照念）**：「这是世界模型 2 秒预测的评估脚本，报告里 MSE 很低。」　**时长** 6–10 分钟

| 级别 | 问题 | 说明 |
|---|---|---|
| P0 | 评估时用 `posterior` 读入了真实的 `obs[:, t+1]` | 每一步都被真实帧"纠正"，评估的是**滤波/重建**能力，不是 2 秒**预测**能力 → MSE 虚低。应只用 prior（动作条件下的纯想象 rollout） |
| P0 | 动作下标错位 | 注释说 `actions[:, t]` 是在 obs t 执行的，转移 t → t+1 应该用 `actions[:, t]`，代码用了 `t + 1`。不报错，模型对动作的响应会显得"迟钝" |
| P2 | 只报告平均 MSE | 像素 MSE 偏好模糊预测；只看平均会掩盖误差随时间的增长。应按时间步报告，再加上下游指标（检测、规划在生成数据上的表现） |

**追问 · 预研**：teacher forcing 训练和自回归 rollout 的差距（曝光偏差）怎么缓解？怎么评估世界模型对动作的"可控性"？
**追问 · 落地**：世界模型用作闭环仿真器时，你最担心什么失效模式（物体消失、动作不响应、长时漂移）？怎么设计能发现这些问题的测试？

**锚点**：4 = 两个 P0 + 指标设计；3 = 找到 posterior 泄漏；2 = 提示后找到；1 = 分不清 posterior 和 prior
