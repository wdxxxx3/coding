# M11 两段式端到端 · `两段式 E2E` `规划` `开环评估`

**入口（照念）**：「检测加规划的两段式端到端，开环 L2 比基线好很多，你信吗？」　**时长** 8–12 分钟（讨论型，无唯一答案）

| 级别 | 问题 | 说明 |
|---|---|---|
| P0 | 训练用 GT 框，推理用检测框 | 训练/推理分布不一致：规划器没见过漏检、误检和抖动，上线后对感知误差非常敏感。可以混合 GT 和预测、加噪声，或直接用检测结果训练 |
| P0 | `ego_state` 里有当前速度、加速度 | 开环 L2 主要由自车状态外推就能拿到（已有研究表明只用自车状态的 MLP 就能达到很低的 L2）。L2 好**不能**证明模型理解了场景 |
| P1 | 开环指标本身 | L2 和碰撞率在不同论文中定义不同（取第 t 秒的值还是 0–t 秒的平均），比较前先确认口径；开环好不等于闭环好 |
| 讨论 | 规划 loss 要不要回传到检测器 | 两段式的取舍：可解释、可单独迭代 vs 端到端联合优化 |

**追问 · 预研**：怎么设计实验证明模型真的用到了感知信息（去掉 ego_state、扰动感知输入）？
**追问 · 落地**：你会用什么闭环评估（日志回放 + 反应式交通、仿真）？上线前哪些指标必须看？

**锚点**：4 = 两个 P0 都能主动提出，并给出证伪实验；3 = 找到一个 P0；2 = 只谈模型结构；1 = 相信开环 L2
