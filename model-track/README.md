# 模型岗题库：按简历选题的"原子卡"

适用：端到端（一段式/两段式）、SFT、VLM、VLA、Flow matching / Diffusion、World model、RL 后训练（PPO/GRPO/DPO）、感知与 RL 小模型；预研岗和落地岗都适用。

## 一句话结论
**领域题应该放，而且是模型岗的主体。**问题不在"需要领域知识"，而在旧题的形式：每道题需要大量上下文，又很难刚好和简历匹配。解决办法是把题目拆成**原子卡**：

- **一张卡 = 一个核心技术点 + 5–12 行代码 + 一句话入口**。不需要额外讲背景：简历上写了 DPO，DPO 的 loss 本身就是上下文
- **只考简历上写了的**。简历写 DPO 就出 DPO 卡，不出 PPO 卡。这样"做不出来"就是真信号，不会和"没接触过"混在一起
- 卡片足够多、粒度足够细，简历上的大部分关键词都能找到 1–3 张对应的卡
- 同一张卡分**预研追问**（原理、推导、为什么）和**落地追问**（延迟、数据、监控、上线），按岗位选

## 45 分钟怎么用

| 时间 | 内容 |
|---|---|
| 0–3′ | 开场（规则同 `docs/02-interview-flow.md`） |
| 3–38′ | **3 张简历卡**，每张 8–12′：入口 → 候选人边读边说 → 找问题 → 1–2 个预研或落地追问 |
| （备用） | **1 张兜底卡**：简历卡都答完了，或者候选人说"这个我其实只是调过参" |
| 38–45′ | 深挖候选人自己的项目，用卡上的"落地追问"把项目问实；候选人提问 |

**面试前 5 分钟**：从简历里圈出 3 个技术点，在下面的匹配表里各选一张卡，再选一张兜底卡。

**面试中的规则**
- 候选人说"这个我没做过"：如果简历上**没写**，直接换卡，反馈表中记为"未覆盖"，不扣分；如果简历上**写了**，那正是这张卡要考察的，继续
- 只展示 `snippet.py` 和入口那一句话。接口约定、形状、单位等由面试官**按需口头补充**，不要预先念一遍
- 参考实现不展示，也不要求候选人写出完整的防御式代码。修复说对了就行

## 旧题库评估：难不难？

**结论**：单个知识点的难度大多适中，但按现在的写法，对校招 45 分钟确实太重了。原因有三：

1. **题面太长**：每道题有十几条接口约定（"布尔值不接受""不修改输入""溢出要报错"……），光读题就要 3–5 分钟。这些约定属于参考实现的严谨性要求，不应该成为候选人的门槛
2. **实现类题（I 系列、A01）要求写完整函数**：又回到了"写代码"，既慢又容易被代答
3. **一部分题偏 infra 或统计**：asyncio 取消、CUDA 计时、聚类 bootstrap、连续碰撞检测。题目好，但和大多数模型岗简历对不上

另外，几处内容需要更正：
- **I01 的示例数字前后矛盾**：题面写 λ = 0.9，但 A₀ = 1.07 + 0.9 × **0.95** × 1.7 = 2.5235 用的是 λ = 0.95。按 λ = 0.9 计算应为 A₀ = 2.4470、y₀ = 2.6470（已用脚本验证）
- **A02 只有标题，正文缺失**（也可能是复制时丢了）
- **R09–R12 只有场景描述，没有代码**，45 分钟内很难推进。R09 现在可以配合 M14 的代码使用
- 粘贴过来的公式有残缺（如 `$$\m$$`），可能只是复制造成的，建议在飞书原文中确认

### 示例：把 R01 改成卡

> **入口**：「这段 REINFORCE 对 mu 的梯度对吗？」
> ```python
> dist = Normal(mu, std); u = dist.rsample()
> reward = simulator(u.clamp(-1, 1).detach())
> loss = -(reward.detach() * dist.log_prob(u).sum(-1)).mean()
> ```
> **面试官要点**：rsample 让 u 依赖 mu，log_prob 沿两条路径求导后对 mu 的梯度恰好抵消为 0 → 改用 `sample()` 或 `log_prob(u.detach())`；不能写成 `log_prob(u).detach()`。追问：裁剪后的动作为什么不能用来算概率？
> **预研追问**：可微模拟器时怎么改成 pathwise？**落地追问**：保存哪个动作才能在 PPO 中重新计算行为概率？

原文中的"深入解析"和"完整参考实现"保留为**面试官的背景材料**，面试中不展示。
