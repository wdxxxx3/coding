# Q11 路测问题定位：无前车急减速（日志推理）

| 项 | 内容 |
|---|---|
| 方向 | 感知 / 融合 / 规控（通用） |
| 形式 | 无代码，日志分析 + 方案权衡 |
| 难度 | ★★★ |
| 建议时长 | 15–18 分钟 |
| 候选人材料 | `candidate/incident.md` |

## 考察点
算法工程师的日常不是写新代码，而是**从日志中定位问题，并在误检和漏检之间做取舍**。这道题的第一步（判断是什么）AI 也能答出来，真正的区分度在第 3、4 问：没有标准答案，只能通过对话展现判断力。

## 参考答案

### 1. obj#57 是什么
**跨线桥（或龙门架、高架标志牌）等上方的静止结构，是雷达的虚警。**依据：
- `rel_v ≈ -22.2 m/s`，正好等于自车速度 80 km/h = 22.2 m/s → 目标**绝对静止**
- 距离每 0.1 s 减少约 2.2 m，与相对速度一致，说明这是一个稳定的真实回波，而不是噪声
- RCS 高（28–31 dBsm），说明是大型金属结构
- 雷达**没有俯仰角测量**，无法区分"路面上的静止物体"和"头顶的桥"
- 相机在 150 m 内始终没有看到车道内有目标
- 越来越近时 RCS 从 31 降到 17 dBsm：目标逐渐离开雷达的垂直波束（因为它在上方）
- 问题单提到"同一路段上周也出现过" → 与位置相关，而不是随机发生

### 2. 各个环节的问题
| 环节 | 问题 |
|---|---|
| 感知/雷达 | 没有俯仰角信息；可以利用 RCS 随距离变化的特征（多径、离开波束）识别上方结构 |
| 融合 | 置信度只看连续检测帧数，静止目标、没有相机确认、类型 UNKNOWN 时，依然只用 3 帧就发布；没有利用地图（地图里可以标注跨线桥位置） |
| 规划 | TTC = 6.2 s 时直接请求 -3 m/s²，没有分级响应；对仅雷达检测、类型未知的目标，和确认的车辆用的是同一套策略 |

### 3. "直接过滤所有仅雷达检测的静止目标"的风险
- 会漏掉**真实的静止障碍物**：故障停车的车辆、事故现场、施工区、掉落的货物
- **对重卡尤其严重**：满载 49 t 在 80 km/h 时，按 3–4 m/s² 减速，仅制动距离就有 60–80 m，再加上气刹建压和反应时间，需要在 100 m 以上就开始响应。**相机的有效距离约 150 m，置信度足够高时往往已经更近了**，而雷达是远距离唯一可靠的来源
- 这是本题的核心：**误刹（舒适性和追尾风险）和漏刹（碰撞）之间的取舍**，而重卡的物理特性让"等确认后再刹"的空间非常小

### 4. 修复与验证（开放，参考方向）
- 分级响应：先松油、预建制动压力（预充），确认后再加大减速度
- 利用高精地图或众包地图标注上方结构位置，在这些位置提高确认门槛
- 4D 成像雷达（有俯仰角测量）
- 多帧特征：RCS 随距离的变化规律、多径特征
- 相机在近距离确认后再提升置信度
- **验证**：在该路段回放；建立"桥下"、"真实静止车辆"两类场景库，同时统计误刹率（每千公里次数）和漏检率，二者都不能变差；仿真注入静止目标

## 追问树
1. 「你是怎么判断它是静止的？」→ 必须用到 rel_v 与自车速度的比较。如果只说"感觉像桥"，追问数字依据
2. 「如果 rel_v 是 -15 m/s 呢？」→ 前方有一个以 7.2 m/s（约 26 km/h）行驶的目标，可能是真实的慢车，不能当虚警
3. 「如果你只能改一个模块，你改哪个？为什么？」→ 考察取舍和沟通，没有标准答案，要能说出理由
4. 「这个修复上线后，你用什么指标来监控？」→ 误刹率、漏检率；按场景（桥、隧道、龙门架）分开统计

## 现场变体（日志可替换）
- 变体 A：场景换成隧道入口，rel_v 同样等于自车速度 → 隧道顶部或入口标志
- 变体 B：rel_v = -14.0 m/s，相机在 120 m 处识别出 type=TRUCK → **这是真实的慢车**，减速是正确的。用来检验候选人是不是背了"桥下误刹"这个答案

## 本题评分锚点
- **4 分**：用数字推理出目标静止，并能结合俯仰角缺失、相机未确认、RCS 变化得出结论；能清楚说明过滤静止目标对重卡的风险，并给出分级响应 + 验证指标
- **3 分**：判断正确，有一定的权衡意识
- **2 分**：判断正确但依据不足，方案只有"过滤掉"
- **1 分**：无法从日志中得出结论
