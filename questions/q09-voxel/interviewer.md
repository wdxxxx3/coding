# Q09 点云体素下采样（找错）

| 项 | 内容 |
|---|---|
| 方向 | 感知（点云） |
| 语言 | C++ |
| 难度 | ★★★ |
| 建议时长 | 15 分钟 |
| 候选人材料 | `candidate/voxel_filter.cc` |

## 考察点
整数取整的语义、哈希键的设计、整数溢出。这几个 bug 都需要**代入具体数值**才能看出来，背题背不出来。重卡对远距离感知的要求（≥ 250 m）会把溢出问题放大。

## 问题清单

| # | 级别 | 问题 | 实测 / 后果 | 修复 |
|---|---|---|---|---|
| 1 | P0 | **键冲突**：(ix, iy, iz) 与 (ix+1, iy-1000, iz) 的 key 完全相同。只要 iy 的取值跨度达到 1000 个格子就会冲突（voxel = 0.1 时，y 方向跨度 100 m，即 ±50 m），iz 同理 | 实测：(0.05, 100.05, 0.05) 和 (0.15, 0.05, 0.05) 被合并，质心是 (0.10, 50.05, 0.05) → **在 50 m 处凭空造出一个点**。大量这样的点会在车道中间形成"幽灵障碍物"，导致误刹 | 使用 int64 并按位打包（如每个维度 21 位加偏移量），或使用 tuple 哈希 |
| 2 | P0 | **整数溢出**：ix = 2147 时 ix·1e6 就超过 INT_MAX，即 voxel = 0.1 时 x > 214.7 m。有符号整数溢出是未定义行为 | UBSan 实测在 230 m 处报 signed integer overflow。重卡要求感知 250 m 以上 | int64 |
| 3 | P1 | `static_cast<int>` **向零取整**，而不是向下取整：(-voxel, voxel) 都落在 0 号格子里，原点附近的格子是其他格子的两倍大 | 实测：voxel = 0.5 时 x = -0.3 和 x = 0.3 被合并。原点附近正是离车最近、最重要的区域，近处的障碍物轮廓被"揉"在一起 | `std::floor` |
| 4 | P1 | NaN / Inf 点：很多雷达用 NaN 表示没有回波。`static_cast<int>(NaN)` 是未定义行为 | 结果不确定 | 先过滤非有限值 |
| 5 | 诱饵 | `grid[key]` 第一次访问时，`std::pair` 默认构造会对两个成员做值初始化 → 全部为 0 | **不是 bug**。候选人能说清楚这一点就加分；如果认为"没有初始化"，可以追问依据 | — |
| 6 | P2 | 如果点云在世界坐标系（UTM，x 约 5e5 m）下，float 的精度只有约 0.06 m，比 voxel 还大 | 格子划分失真 | 先减去局部原点，或用 double |
| 7 | P3 | unordered_map 的遍历顺序不确定 → 输出顺序不确定 → 下游结果不可复现；没有 reserve | 调试困难，性能问题 | 排序或使用确定性的容器；reserve |

## 提示阶梯
- L1：「挑两个具体的点算一下 key。」
- L2：「y = 100 m、voxel = 0.1 时，iy 是多少？iy*1000 呢？」
- L2'：「x = -0.3 和 x = 0.3，voxel = 0.5，ix 分别是多少？」

## 追问树
1. 「你会怎么设计 key？」→ `(int64(ix) + OFFSET) << 42 | (int64(iy) + OFFSET) << 21 | (int64(iz) + OFFSET)`，并说明每个维度的取值范围；或者使用 `std::hash` 组合（需要处理哈希冲突时比较完整键）
2. 「用质心代替还是保留离格子中心最近的真实点？各有什么优缺点？」→ 质心更平滑但会产生"不存在的点"；保留真实点更保真
3. 「200k 点、5 ms 的预算，怎么加速？」→ 排序代替哈希、并行、GPU
4. 「远处点稀疏、近处点密集，固定大小的 voxel 合理吗？」→ 按距离自适应

## 现场变体
- 变体 A：key 改为 `std::to_string(ix) + "," + ...` → 正确但很慢，讨论性能
- 变体 B：改用 `std::map<std::tuple<int,int,int>, ...>` 但保留 `static_cast<int>` → 只剩 #3

## 本题评分锚点
- **4 分**：独立发现 #1、#2、#3，能举出具体数值的反例，给出合理的 key 设计，并能确认诱饵正确
- **3 分**：发现 #1 或 #2，加上 #3
- **2 分**：在提示下发现键冲突
- **1 分**：说不清 key 的作用
