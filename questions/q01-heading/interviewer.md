# Q01 航向角工具函数（阅读 + 找错）

| 项 | 内容 |
|---|---|
| 方向 | 通用 / 规控 / 预测 |
| 语言 | Python |
| 难度 | ★★（适合作为第一题热身） |
| 建议时长 | 12–15 分钟 |
| 候选人材料 | `candidate/heading_utils.py` |

## 考察点
角度的周期性（wrap）几乎是所有自动驾驶模块都会踩的坑。这道题看候选人是否会**主动带入边界场景**（车往正西开），而不只是读懂公式。

## 问题清单（面试官答案）

| # | 级别 | 位置 | 问题 | 车上的后果 | 修复 |
|---|---|---|---|---|---|
| 1 | P0 | `compute_headings` | `atan2(dx, dy)` 参数反了，应为 `atan2(dy, dx)`。向东行驶得到 π/2 而不是 0 | 所有航向错位约 90° 并镜像，横向控制直接失效 | `atan2(dy, dx)` |
| 2 | P0 | `heading_error` | 差值没有归一化到 [-π, π]。target=179°、current=-179° 时误差为 358°，实际只差 -2° | 车辆朝正西行驶时，横向控制器突然输出极大转角，"甩方向" | `normalize(target - current)` |
| 3 | P0 | `smooth_headings` | 直接对角度做算术平均。`[3.10, 3.14, -3.14, -3.10]` 平滑后变成 `[1.03, 0, 0, -1.03]`（已实测），朝西行驶被平滑成朝东 | 航向翻转 180°，下游轨迹、预测全错 | 圆周均值：`atan2(mean(sin), mean(cos))`，或先 unwrap 再平均 |
| 4 | P1 | `heading_rate` | 同样没有 wrap，跨越 ±π 时出现约 2π/dt 的尖峰 | 横摆角速度估计出现尖峰，触发异常检测或控制抖动 | 差值先归一化 |
| 5 | P1 | `compute_headings` | 相邻点重合（停车、轨迹点重复）时 `atan2(0,0)=0`，航向突跳到 0 | 低速/停车时航向乱跳 | 距离小于阈值时沿用上一个有效航向 |
| 6 | P2 | `compute_headings` | 输入少于 2 个点时 `headings[-1]` 抛 IndexError | 偶发崩溃 | 边界检查 |
| 7 | P2 | `heading_rate` | `dt=0` 除零 | 同上 | 参数校验 |
| 8 | P3 | 全局 | `numpy` 导入了但没用，逐点循环性能差 | 可读性/性能 | 向量化 |

**期望**：合格的校招生 10 分钟内能找到 #2、#3 中的至少一个，并说清后果。找到 #1 是加分项（需要对照背景里的坐标系约定）。

## 提示阶梯（每用一级，"问题发现"维度最高分降一档）
- L1：「这些函数在什么输入下会出问题？试试极端值。」
- L2：「如果车往正西开，heading 大约是多少？」
- L3：「`heading_error(179°, -179°)` 返回多少？」直接让他算

## 追问树
1. **手算**：「`smooth_headings([3.10, 3.14, -3.14, -3.10])` 输出什么？」看他是否真的动手算，而不是背结论
2. **手写**（3 分钟，可作为微型手写题）：「写一个 `normalize_angle(a)`。」
   - Python：`(a + pi) % (2*pi) - pi`
   - 追问：「同样的写法在 C++ 用 `fmod` 对吗？」→ `fmod` 结果可以是负数，需要额外处理
   - 追问：「用 `while a > pi: a -= 2*pi` 有什么问题？」→ 输入是 1e10 或 NaN 时会卡死
3. **领域加分**：「重卡是牵引车加挂车，铰接角 = 牵引车航向 − 挂车航向。这个量要注意什么？」→ 同样需要 wrap；挂车航向通常是估计值，噪声更大
4. **设计**：「为什么航向要从位置差分算？有更好的来源吗？」→ 定位直接输出的航向 / IMU 积分；位置差分在低速时噪声大

## 现场变体（防止题目泄露）
- 变体 A：把 #1 改正确，在 `heading_rate` 里把 `/ dt` 改成 `* dt`
- 变体 B：`smooth_headings` 改为 `np.convolve` 实现，同样的问题换一种写法

## 本题评分锚点
- **4 分**：主动带入 ±π 场景，找到 #2、#3、#4，给出圆周均值方案，并主动提到 C++ `fmod` 等实现细节
- **3 分**：找到 #2 或 #3，后果说得清楚，修复正确
- **2 分**：需要 L2 提示才发现 wrap 问题，修复方案基本正确
- **1 分**：L3 提示后仍说不清问题在哪
