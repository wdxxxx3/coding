# Q02 BEV 框 IoU 与 NMS（找错）

| 项 | 内容 |
|---|---|
| 方向 | 感知 |
| 语言 | C++ |
| 难度 | ★★ |
| 建议时长 | 15 分钟 |
| 候选人材料 | `candidate/nms.cc` |

## 考察点
很多人在学校写过 NMS，但这里的 bug 分属不同层次：数学（IoU 公式）、C++ 语义（迭代器失效）、领域判断（类别、旋转框）。可以区分"背过"和"理解过"。

## 问题清单

| # | 级别 | 问题 | 后果 | 修复 |
|---|---|---|---|---|
| 1 | P0 | 并集少减了交集：应为 `area_a + area_b - inter`。两个完全相同的框 IoU 只有 0.5 | 阈值 ≥ 0.5 时什么都不会被抑制 → 同一个目标出现多个重复框 → 规划看到"一群车"，可能误刹 | 修正公式 |
| 2 | P0 | `w`、`h` 没有截断到 0。两个对角方向不相交的框，w、h 都为负，乘积为正。实测 `(0,0,2,2)` 与 `(3,3,5,5)` 的 IoU = 0.125 | 不相交的框被误抑制 → **漏检**（真实目标被删掉） | `w = max(0, ...)`，`h = max(0, ...)` |
| 3 | P0 | 按分数**升序**排序，每次留下的是分数最低的框 | 保留了最差的框，定位精度下降，置信度错误 | 降序 `a.score > b.score` |
| 4 | P0 | 在 for 循环里 `erase(it)` 后又 `++it`：迭代器失效，未定义行为。ASan 实测报 heap-buffer-overflow | 偶发崩溃，或跳过元素导致漏删 | `it = boxes.erase(it)` 否则 `++it`；或用 `remove_if` |
| 5 | P1 | 不区分类别：大车的框会抑制旁边的行人 | 行人站在车旁边时被删掉 | 按 label 分组做 NMS（或明确这是设计选择） |
| 6 | P1 | 轴对齐框不适合斜向的长车：18 m 挂车斜着停时，轴对齐框很大，相邻车道的车也会被抑制 | 重卡场景中，挂车、车辆运输车等长目标经常互相误抑制 | 旋转框 IoU |
| 7 | P2 | 两个面积为 0 的框会除以 0，得到 NaN | 退化框导致 NaN，比较结果不可预期 | 分母加 eps |
| 8 | P3 | `vector::erase(begin())` 是 O(n)，整体 O(n²) | 候选框多时变慢 | 用标记数组代替删除 |

**期望**：合格者能找到 #1、#2、#3、#4 中的 3 个。#4 需要 C++ 基础；Python 背景的同学可以降低这一项的权重。

## 提示阶梯
- L1：「用两个具体的框验证一下 IoU。」
- L2：「两个完全一样的框，IoU 应该是多少？这里算出来是多少？」
- L3：直接指出某一行

## 追问树
1. **后果权衡**：「NMS 阈值调高和调低，分别会导致什么？对规划来说，重复框和漏检哪个更危险？」→ 重复框导致误刹（舒适性/追尾风险），漏检导致碰撞；不同类别取舍不同
2. **重卡场景**：「挂车经常被检测成"牵引车 + 挂车"两个框，或者一个长框被切成几段。NMS 层面能解决吗？」→ 超出 NMS 的能力，需要在检测头或跟踪层处理；看候选人是否知道一个模块的能力边界
3. **C++**：「为什么 `boxes` 按值传入？」→ 函数内部需要修改，按值传入是合理的，不算 bug（诱饵）
4. **性能**：「1000 个候选框、每帧 10 ms 的预算，怎么优化？」→ 先按分数阈值过滤、空间网格加速、GPU 实现

## 现场变体

- 变体 B：改成 Python 版本，#4 换成"遍历列表时 remove"
