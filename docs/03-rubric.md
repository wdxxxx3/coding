# 评分标准

## 五个维度

| 维度 | 权重 | 看什么 |
|---|---|---|
| A. 代码理解 | 25% | 能否准确说出代码在做什么、输入输出、单位、隐含的假设 |
| B. 问题发现 | 25% | 找到的问题数量与严重程度；能否给问题分级；**能否识别诱饵**（不把正确的代码当成 bug） |
| C. 后果推演 | 20% | 能否把 bug 和车上的具体现象联系起来，并给出量级（"偏 2.5 m"而不是"会不准"） |
| D. 修复与验证 | 20% | 修复是否正确；能否设计出能抓住这个 bug 的测试 |
| E. 沟通与思考过程 | 10% | 思路是否清晰、是否主动提问、不确定时是否诚实、追问之下能否深入 |

## 通用锚点（每道题的 `interviewer.md` 中有更具体的锚点）

| 分数 | 含义 |
|---|---|
| 4 | 独立完成，超出预期。有领域洞察，或主动发现了题目没有要求的问题 |
| 3 | 基本独立完成，达到校招合格线。可能用到 L1 提示 |
| 2 | 需要 L2 提示才能推进，或理解有偏差但能被纠正 |
| 1 | L3 提示后仍无法推进 |

**提示阶梯与分数的关系**：使用 L1 提示时，该题"问题发现"维度最高 3 分；使用 L2 时最高 2 分；使用 L3 时最高 1 分，只考察后果和修复。

## 结论

加权平均分：

| 加权平均分 | 结论 |
|---|---|
| ≥ 3.3，且没有维度低于 2 | 强烈推荐 |
| 2.8–3.3 | 推荐 |
| 2.3–2.8 | 待定（可加面一轮） |
| < 2.3 | 不推荐 |

## 可信度标记（单独记录，不计入分数）

如果出现下面的情况，在反馈表中**如实记录事实**，不下结论：

- 回答前有固定的停顿，然后输出一大段流畅、书面化、条目完整的内容
- 第一轮回答很完整，但追问一层就答不上来，或者答非所问
- 无法回答"你是怎么注意到这里的"
- 把题目中的诱饵也当成 bug，并且说法和标准的 AI 回答高度相似
- 不记得自己几分钟前说过的结论，前后矛盾
- 视线频繁偏向屏幕外的固定位置

**有两条或以上可信度标记时**，无论分数如何，结论最高为"待定"，并建议安排现场或有监考的验证面试（抽一道题换变体，约 15 分钟）。
